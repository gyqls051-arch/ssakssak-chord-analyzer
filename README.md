# 음원 코드/조성 분석기

mp3/wav(및 flac/m4a/ogg) 파일을 분석해서 **코드 진행**과 **조성(키)**을 추출하는 도구입니다.

> ⚠️ **참고용 근사치입니다.** 완벽한 정확도를 보장하지 않으며, 특히 디스토션 기타나
> 신스 레이어가 많은 밴드 음악은 정확도가 떨어질 수 있습니다. 실제 채보를 대체할
> 수 없습니다.

## 가장 쉬운 사용법 (GUI 프로그램)

**`dist/SsakSsakChordAnalyzer.exe`를 더블클릭**하세요. 파이썬 설치가 필요 없습니다.

1. **[🎵 음원 파일 열기]** — mp3/wav 파일 선택
2. **[▶ 분석 시작]** — 버튼을 눌러야 분석 시작 (진행바로 6단계 진행 상황 표시)
3. 조성(스케일), BPM, 코드 진행이 창 안에 표시됨

파일은 자동으로 만들어지지 않습니다. 필요할 때만 내보내기 버튼으로 저장:

| 버튼 | 저장 내용 |
|---|---|
| 📄 문서 내보내기 | 분석 결과 텍스트 (.txt) |
| 🖼 이미지 저장 | 코드 타임라인 그림 (.png) |
| 🎹 MIDI 저장 | 코드 진행 미디 파일 (.mid) — DAW/미디 플레이어에서 재생 가능 |

저장 위치는 매번 직접 선택할 수 있습니다 (기본값: 음원 파일 옆).

## 파이썬으로 직접 실행

```bash
pip install -r requirements.txt
python analyze.py --input song.mp3 --output chords.txt
```

mp3 파일을 다루려면 시스템에 `ffmpeg`(또는 audioread가 지원하는 디코더)이 설치되어
있어야 할 수 있습니다.

### 옵션

| 옵션 | 설명 | 기본값 |
|---|---|---|
| `--input` | 입력 오디오 파일 경로 (필수) | - |
| `--output` | 결과 텍스트 파일 경로 | `chords.txt` |
| `--sevenths` | 7th 코드(maj7, 7, m7)까지 확장 인식 | 꺼짐 (트라이어드만) |
| `--min-duration` | 스무딩 최소 지속 비트 수 (짧게 튀는 코드 제거) | `2` |
| `--visualize` | 코드 타임라인 PNG 이미지도 저장 | 꺼짐 |

### 예시

```bash
python analyze.py --input song.mp3 --output chords.txt --sevenths --visualize
```

## 동작 원리 (FMP 교과서 + librosa 공식 예제 표준 기법)

1. **오디오 로드** — `librosa.load`로 mp3/wav를 읽어들입니다.
2. **강화 크로마 추출** — 3단계 파이프라인:
   `librosa.effects.harmonic(margin=8)` 하모닉 분리 →
   `librosa.feature.chroma_cqt` CQT 크로마그램 →
   `librosa.decompose.nn_filter` + median filter로 노이즈/경과음 억제
3. **비트 검출** — `librosa.beat.beat_track`으로 BPM과 비트 위치를 추출.
   비트가 4개 미만이거나 비트 간격 중앙값이 1.5초를 넘으면(BPM<40 = 오검출 가능성)
   0.5초 균등 그리드로 자동 대체합니다.
4. **비트 단위 집계** — 비트 경계 사이의 평균 크로마를 계산합니다.
5. **코드 인식** — 24개(또는 `--sevenths` 시 60개) 코드 템플릿과의 코사인 유사도를
   softmax 확률로 변환한 뒤, **Viterbi 디코딩**(`librosa.sequence.viterbi_discriminative`,
   자기유지 확률 0.9)으로 시퀀스 전체를 한 번에 최적 추정합니다.
   에너지가 거의 없는 구간은 `N.C.`(무화음)로 표시합니다.
6. **후처리 스무딩** — Viterbi 후에도 남은 최소 지속(기본 2비트) 미만의 튐을
   인접 구간에 흡수시킵니다.
7. **조성 추정** — Krumhansl-Schmuckler 키 프로파일 알고리즘으로 곡 전체 크로마
   분포와 24개 키(장조 12 + 단조 12) 프로파일을 비교해 가장 근접한 키와
   confidence 점수를 계산합니다.
8. **패턴 감지** — 추정된 키를 기준으로 코드를 로마 숫자 디그리로 변환한 뒤,
   `I-V-vi-IV`, `ii-V-I` 등 흔한 진행 패턴이 있는지 검사합니다.

## 유지보수

### 테스트 실행 (코드 수정 후 필수)

```bash
python test_analyze.py
```

39개 테스트: 템플릿 생성, 코드 이름 파싱(샤프 루트 회귀 포함), 로마 숫자 변환,
조성 추정, 스무딩, 패턴 감지, 합성 음원 통합 테스트, 에러 처리.

### exe 재빌드

`build_exe.bat`을 더블클릭하면 가상환경 생성 → 의존성 설치 → 테스트 → 빌드까지
자동으로 진행됩니다 (수 분 소요). 결과물은 `dist/SsakSsakChordAnalyzer.exe`
(GitHub Releases에는 ASCII 파일명으로 배포).

### 파일 구조

| 파일 | 역할 |
|---|---|
| `analyze.py` | 분석 로직 전체 (CLI로도 단독 실행 가능) |
| `gui.py` | GUI 껍데기 — 분석은 analyze.py 를 그대로 호출 |
| `test_analyze.py` | 테스트 스위트 (39개) |
| `build_exe.bat` | 원클릭 빌드 스크립트 |
| `dist/SsakSsakChordAnalyzer.exe` | 배포용 GUI 프로그램 |

### 주요 튜닝 상수 (analyze.py 상단)

| 상수 | 의미 | 기본값 |
|---|---|---|
| `SOFTMAX_GAMMA` | 유사도→확률 첨예도 (높을수록 단정적) | 12.0 |
| `SELF_TRANSITION` | Viterbi 자기유지 확률 (높을수록 코드 변화에 보수적) | 0.9 |
| `ENERGY_THRESHOLD` | 이보다 약한 구간은 N.C. 처리 | 1e-4 |
| `FALLBACK_GRID_SEC` | 비트 검출 실패 시 그리드 간격(초) | 0.5 |
| `MAX_BEAT_INTERVAL` | 비트 간격이 이보다 크면 오검출로 판단(초) | 1.5 |

## 출력 예시

```
============================================================
코드 진행 분석 결과 (참고용 근사치입니다)
============================================================
파일: song.mp3
길이: 3:24   추정 BPM: 120.5
추정 조성: C Major  (confidence: 0.87)
------------------------------------------------------------
[0:00-0:04] C  [0:04-0:08] Am  [0:08-0:12] F  [0:12-0:16] G
------------------------------------------------------------
감지된 흔한 코드 패턴: I-vi-IV-V

결과가 저장되었습니다: chords.txt
```

`chords.txt`에도 동일한 내용이 텍스트로 저장됩니다. `--visualize` 옵션을 주면
`<output파일명>_timeline.png`로 코드 타임라인 이미지도 함께 저장됩니다.

## 에러 처리

- 존재하지 않는 파일 경로 → 오류 메시지 출력 후 종료
- 지원하지 않는 확장자 → 오류 메시지 출력 후 종료
- 오디오 로드 실패(손상된 파일 등) → 오류 메시지 출력 후 종료
- 비트 검출 실패 시 0.5초 간격 균등 그리드로 자동 대체
